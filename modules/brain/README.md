# BRAIN module

The module stores source metadata, immutable source versions and chunks, extraction signals, claims, promoted facts, scoped memory and versioned procedural knowledge. `contracts.ts` models the seven memory categories named in Protocol 06 §38: preference, fact, project state, decision, procedure, tool knowledge and historical outcome. The architecture overview separately calls for five memory types but does not name them, and neither the WP-BRAIN requirements nor the located project input index resolves the five names. This implementation keeps the explicit Protocol 06 categories and records the count/name discrepancy as an open mapping gap.

## Security and data boundaries

Every row repeats tenant and workspace identifiers. Composite references, RLS policies and `LocalScopedStore` scope reads and writes. Hybrid retrieval places tenant and workspace predicates in the SQL candidate CTE before keyword rank or vector distance is calculated. Results preserve source/version/chunk citations and set `untrusted: true`; a retrieved passage can never grant tool authority. The embedding index is nullable: keyword/full-text retrieval continues when an embedding or vector index is unavailable. Embeddings record model, version and dimension and remain derived indexes, not truth.

Facts are append-only and require a matching persisted claim plus promotion provenance. The API separates agent claim creation from reviewer/policy promotion, and the database trigger validates claim equality and rejects app-role fact inserts without reviewer provenance. Contradictions are recorded when claims conflict with effective facts. A later fact suppresses an earlier fact only through its explicit `supersedes_id` edge and only while the superseding fact's own effective interval is active. `factsAsOf` therefore restores a predecessor after a temporary successor expires, provided the predecessor itself remains in interval. Regression tests cover a later co-predicate fact with no supersession edge and a temporary superseder that expires.

## Retention and procedures

Source deletion uses `RESTRICT` across derived records, intentionally preventing silent evidence loss. Approved erase requests persist tenant/workspace scoped intent, retention policy, source blob references, retry counts, and immutable attempt audit rows. The current CLOUD API has no durable object-reference checker or idempotent deletion/audit contract; ADR-0016 also reserves hard purging for a privileged server path that the module host has not exposed. BRAIN consequently leaves requests `waiting_cloud`, retains source and derived records, and never deletes R2 objects; database guards reject app-role status transitions or completion without privileged audit evidence. `REQ-DATA-005` remains PARTIAL until a coordinated server and Cloud workflow can check shared-object references, honor legal holds/retention, purge all derived indexes and records, and provide durable completion evidence. Procedural candidates from workflow runs are not usable as approved procedures until a reviewer appends an approved version.

## Reduced modes and open verification

No embedding provider is implemented here. Ingestion creates keyword-searchable chunks; a trusted local integration may supply versioned embeddings. Omitting query vectors uses keyword mode; vector-query failures fall back to keyword results. The module migration provisions pgvector and must be verified against both PGlite and Neon. If the extension is unavailable at migration time, the module cannot be installed yet. An independent twelve-query, one-relevant-source-per-query labeled corpus and Recall@10 regression test are included; the measured threshold remains PARTIAL until the suite is run successfully. `listMemories` uses a bounded (maximum 100), keyset-paginated page with an optional memory type filter. Functional Truth and Procedures forms call the declared read/write capabilities, but their host capability handlers must be registered by the application integration. Complete UI state/accessibility automation, measured visual parity, and source/blob deletion integration remain PARTIAL.
